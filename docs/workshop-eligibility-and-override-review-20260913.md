# Workshop eligibility and location review

The overview rebuilt each station's eligibility three times and calculated each vehicle's hours twice. It also dropped Yard Hold vehicles even when the station planner correctly considered them eligible. The read functions now calculate those results once per request and include Yard Hold candidates and a separate Yard Hold waiting count.

On the staging data, three database execution measurements had medians of 15,595.6 ms before and 2,892.9 ms after (81.5% faster). This measures the database function, not the complete page load. Candidate count increased from 381 to 382, adding the missing Yard Hold vehicle. Existing PMB/IT candidate details, station eligibility, revisions and pipeline counts matched the previous response.

Location overrides previously changed what Vehicle Locations displayed but workshop eligibility and scheduling still used the imported location. The workshop now uses the override when one is set, including the overview, station snapshot, manual booking/moves, Book all, restore eligibility and ETA validation. Source/Navision location remains stored separately. Clearing the override restores the source location's scheduling rules; an IT override still requires ETA plus seven days, while PMB and Yard Hold need no ETA.

Verification uses temporary synthetic operators, vehicles, operations and bays in single transactions that end with ROLLBACK. The existing 38-case operation approval/cascade suite passed again. Added coverage checks 16 eligibility cases and 25 override/scheduling cases, including missing hours, location aliases, hidden/completed vehicles, anonymous access, manual moves, Book all across stations, Sublet exclusion, the five-hour handover gap and unchanged pre-existing records. Changing or clearing an override recalculates ETA warnings while preserving existing booking times. No real customer operation was approved by these tests.

The fixed schedule remains Monday–Friday 07:00–17:00, Saturday 08:00–12:00 and Sunday closed. The cascade regression suite covers multi-day work, Admin blocks, technician assignments, started/stopped jobs, protected conflicts, stale approvals and idempotent retries.

An additional 17-case rolled-back database suite exercises exact Saturday start/end boundaries, Sunday closure, Saturday-to-Monday continuation, manual Admin and bay overlap rejection, technician leave, Sublet absence and expected-return boundaries, stale moves and unchanged pre-existing records. The four database suites total 96 passing cases.

Best slot was validating every occupied minute by restarting the calendar calculation from the beginning of the job. A 57-hour validation made 26,821 availability-window calls. It now visits the occupied work windows once (14 calls in the same case) and eliminates conflicting candidates before further validation. Search stops at the loaded authoritative date boundary. Trial bookings use the bay's default mechanic or the vehicle fallback; existing bookings preserve their assigned mechanic, and manual suggestions use the selected mechanic. This allows loaded mechanic conflicts and leave across the entire job to affect the suggestion.

For a synthetic 57-hour job behind an existing 40-hour bay booking, three local Node measurements gave a median of 19,152.7 ms before and 18.45 ms after. Both versions selected Friday 18 September at 07:00. This measures the planner computation, not a full browser page or network request. The old and new validators agreed on 264 calendar cases, with another 72 independent comparisons covering irregular breaks, closures, leave and overtime. Fourteen new runtime regressions cover mechanics, exact handover boundaries, Admin/bay conflicts, calendar continuation and bounded search; the existing handover, exact-minute, weekday and current-time recompute suites also pass.

The client can reject mechanic conflicts only for bookings present in its loaded snapshot. A mechanic's booking in another unloaded station or date range is still checked by the authoritative database when saving, and may reject the proposed slot. This release does not add a global technician-booking fetch. The tests describing other-station mechanic conflicts explicitly supply a loaded booking; they do not claim to exercise an additional remote query.

## Coverage and reporting

The forward-clock regression moves an already-booked vehicle's arrival date later, then verifies the clock carries that booking and its bay/cross-station followers into permitted future working time. It retains allocated hours, expands capacity for added work, and preserves identity, history, workshop opening times and the one-hour vehicle handover. It also checks that the temporary conflict cache is cleaned up and cannot be spoofed by a caller. The full copied-backlog scenario compares preview and persisted movements, rejects any remaining overdue planned work, and checks that allocated hours are never reduced. A successful scheduler process alone is insufficient: inspect the clock result and per-bay errors, because a rejected component can return normally without moving its work.

The returned-booking regression returns synthetic reservations to Unallocated, then reserves a compatible bay again through ordinary and cascade moves. It checks retained booking identity, restored planned status, stale-version rejection, protected lifecycle transitions, original work/history and cleanup. It selects open dates from the configured calendar. The forward-clock regression also verifies that a returned, unstarted reservation without a bay remains unchanged and cannot freeze booked work for the same vehicle. These are isolated database checks, not actual browser dragging.

The Start regression also covers a booked job whose other stations have been returned to Unallocated. Their retained historical/future dates must not enter Start's collision or write-order plan. It checks a successful actual-now start, unchanged Unallocated rows and versions, preserved hours, and unchanged existing vehicles/bookings. Run it alongside Start priority/cascade and running/stopped safety scenarios so a fix cannot remove genuine protections.

The fitter destination-bay regression also moves an unstarted booking between two synthetic bays, then reads the destination mechanic's queue and checklist through the restricted fitter refresh path. It checks retained assignment history, manual overrides, same-bay time moves and technician conflicts, including a soft-deleted booking whose retained assignment must not block the destination fitter. It runs only in the disposable loopback database and does not establish real iPad UI interaction.

The work-category regression checks separate Bus Mechanical/Electrical/QA estimates and reservations, remaining categories in the real station response, category-only fitter checklists and completion, explicit zero-hour QA tasks, changed operation estimates, saved manual category choices, protected whole-job bookings, and Book all. It verifies that existing operational bookings are unchanged by these fixture scenarios. The hourly browser-code suite also checks category projection and shared destinations. These are not browser dragging tests.

The accepted-import regression follows synthetic uploaded operations through automatic acceptance into canonical categories and fitter checklists. It checks explicit source hours, later hour updates, external Pit and zero-hour QA, separate Mechanical/Electrical reservations, existing whole-job bookings, retained manual categories, QC protection and explicit missing-category/hour exceptions. It also verifies that existing copied vehicles and bookings stay unchanged. Actual provider email delivery remains outside this SQL coverage.

The automatic-additions regression verifies learned AI routing, information-only jobcard notes, provisional hours without altering source hours, replay safety, private worker permissions and protected additions appearing on the owning vehicle card. Ordinary accepted-jobcard additions no longer require the Operation Updates page. See `tools/import-routing/README.md` for the worker contract; the initial New Vehicles and completed-work protections remain active.

These checks do not establish that every possible situation works. Report PASS, FAIL, BLOCKED and NOT RUN separately. Distinguish a stale fixture/backup or missing test capability from a confirmed website defect.
